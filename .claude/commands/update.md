# /update: מעדכנים את הסוכן לגרסה החדשה

בדרך כלל העדכון נכנס לבד, בתחילת הריצה היומית. הפקודה הזו נדרשת כשהמייל כתב "יש גרסה חדשה... כתבו ל-Claude: תעדכן את הסוכן". זה קורה כשהמשתמש שינה בעצמו קוד, והשינוי שלו מתנגש עם הגרסה החדשה.

1. מריצים `node scripts/update.mjs`. אם כתוב "הסוכן עודכן" או "הסוכן מעודכן", סיימנו.
2. **אם יש שינוי שלא נשמר:** `git status`. מראים למשתמש במשפט אחד מה השתנה, ושואלים אם לשמור את השינוי שלו (`git add` ו-`git commit`), או לבטל אותו.
3. **אם יש התנגשות:**
   1. מאתרים את הגרסה האחרונה: `git tag --list "v*" --sort=-v:refname`, הראשונה ברשימה.
   2. בודקים שהיא חתומה: `node -e "import('./scripts/update.mjs').then(m=>console.log(m.SIGNERS))" > data/.allowed-signers`, ואחריו `git -c gpg.format=ssh -c gpg.ssh.allowedSignersFile=data/.allowed-signers verify-tag <התג>`. **אם הבדיקה נכשלה, עוצרים**, ולא ממזגים בשום מקרה.
   3. ממזגים: `git merge <התג>`.
   4. פותרים כל התנגשות כך שגם השינוי של המשתמש וגם התיקון החדש נשמרים. בכל ספק שואלים את המשתמש.
   5. מריצים `npm ci` ו-`npm test`. רק אם הכול עובר, מסיימים את המיזוג.
4. **בסוף:** אומרים למשתמש לאיזו גרסה עודכן, ומה חדש לפי `CHANGELOG.md`, בשתי שורות.
