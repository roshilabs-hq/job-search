# /start: מקימים את סוכן חיפוש העבודה

אתה מלווה את המשתמש מאפס עד סוכן שרץ לבד: ריאיון היכרות, קורות חיים, הגדרות, מייל ותזמון. בסוף הדרך הסוכן מחפש משרות פעמיים ביום ושולח סיכום במייל.

**איך מדברים:**
- עברית פשוטה וחמה, בגוף שני.
- הודעות קצרות ושאלה אחת בכל פעם.
- בלי "פשוט", "קל" ו"רק".
- כל מונח טכני מוסבר במשפט.
- את מה שאפשר לעשות במחשב אתה עושה בעצמך. המשתמש עושה רק מה שדורש את הידיים שלו: לענות, לאשר, להדביק סיסמה.

**התקדמות נשמרת:** בסוף כל שלב כתוב שורה ב-`data/setup-progress.md`. אם הקובץ קיים כשמתחילים, קרא אותו, ספר למשתמש איפה עצרתם, והמשך משם.

---

## שלב 0: בודקים שהכול מותקן (בלי לשאול)
1. מריצים `npm ci` ואחריו `npm run check -- --tools`. היא בודקת רק את הכלים: Node.js, Git, Claude Code ו-Edge. כל השאר נבנה בהמשך.
2. אם Node.js חסר: מסבירים במשפט ("Node.js הוא המנוע שמריץ את הסוכן"), ומבקשים אישור להריץ `winget install OpenJS.NodeJS.LTS`. אחרי ההתקנה צריך לפתוח את Claude Code מחדש.
3. כותבים למשתמש בשלוש שורות מה עומד לקרות:
   - ריאיון קצר, כדי שהסוכן יכיר אותך (כ-15 דקות).
   - כמה הגדרות: איפה, איזה שכר ואילו תחומים (כ-5 דקות).
   - הגדרת מייל והפעלה (כ-10 דקות).

## שלב 1: ריאיון היכרות וקורות חיים
**למה:** הסוכן נותן ציון לכל משרה לפי מה שהוא יודע עליך. ככל שהוא מכיר אותך טוב יותר, הציונים וקורות החיים המותאמים מדויקים יותר.

1. שואלים: "יש לך קורות חיים? אם כן, גרור את הקובץ (PDF) לחלון הזה. אם הוא ב-Word, שמור אותו קודם כ-PDF (קובץ ← שמירה בשם ← PDF)."
   - **יש קובץ:** קרא אותו. מעכשיו אתה שואל רק מה שחסר או לא ברור.
   - **אין קובץ:** בונים מאפס, באותו ריאיון.
2. **שיטת הריאיון: שאלה אחת בכל פעם, עם תשובה מוצעת.**
   - דוגמה: "בקורות החיים כתוב שניהלת צוות. כמה אנשים היו בו? (לפי מה שכתוב נראה 4, נכון?)"
   - על תשובה כללית לא ממשיכים, שואלים שאלת המשך: "חסכת כסף לחברה? בערך כמה?". אם המשתמש לא יודע, מסמנים `[---למלא---]` וממשיכים.
   - עד כ-20 שאלות בסך הכול.
   - אחרי כל 5 שאלות מזכירים: "אפשר לעצור ולהמשיך מחר, הכול נשמר". כותבים את התשובות ל-`data/setup-progress.md`.
   - סדר הנושאים:
     1. מה התפקיד הנוכחי או האחרון.
     2. כל תפקיד בנפרד: מה עשית, כמה אנשים ניהלת, 2–3 הישגים עם מספרים, ובאילו מערכות עבדת.
     3. השכלה.
     4. שירות צבאי או לאומי, אם היה.
     5. שפות.
     6. פרטי קשר לראש הקובץ: שם, עיר, טלפון ומייל.
3. **מה מחפשים ומה לא:**
   - תפקידים ותחומים.
   - רמת בכירות.
   - מה לא רלוונטי בשום מקרה.
   - **מה חשוב לך, ובאיזה סדר:** למשל ניהול צוות, עבודה מהבית, יציבות או קידום.
4. **כללי קורות החיים:** לפי `vendor/israeli-cv-builder/SKILL_HE.md`, שלבים 2–5:
   - בלי גיל, תמונה, מצב משפחתי ותעודת זהות.
   - בלי פרופיל צבאי.
   - עיר בלבד, בלי כתובת.
   - עמוד אחד.
   - שורות שמתחילות בפועל, עם מספרים.
   - עברית ישירה.
   - **לא ממציאים כלום.**
5. כותבים שני קבצים:
   - `cv/base-cv.json`, במבנה של `cv/base-cv.example.json`.
   - `profile.md`, במבנה של `profile.example.md`: מי אני, מה אני מחפש, מה לא רלוונטי, ומה חשוב לי מהכי חשוב.
6. מריצים `node --no-deprecation tailor-cv.mjs --base` ופותחים את ה-PDF (`start "" "<הנתיב>"`). מבקשים מהמשתמש לעבור עליו. מה שהוא מתקן נכנס ל-`base-cv.json`, ואז מייצרים שוב.

**דילוג:** מי שאומר "רק תעלה את הקובץ ותתחיל" מקבל המרה של הקובץ ל-`base-cv.json` ופרופיל קצר משלוש שאלות: מה מחפשים, מה לא, ומה חשוב. אומרים לו פעם אחת: "הציונים יהיו פחות מדויקים. אפשר להשלים את הריאיון מתי שתרצה: תכתוב 'בוא נשלים את הריאיון'".

## שלב 2: איפה, כמה, ואילו תחומים
1. **אזור:** "באיזה אזור אתה מחפש? אפשר ערים, אזור (צפון, מרכז, שרון...), או 'כל הארץ'. ומה לגבי עבודה מהבית או היברידית?"
   - כותבים ל-`settings.json`, בתוך `area`:
     - `places`: כל עיר בעברית **ובאנגלית**, ומילות אזור. למשל: חיפה, Haifa, הקריות, קריית ביאליק, Kiryat Bialik, צפון.
     - `anywhere`: true ל"כל הארץ".
     - `remote`: true אם עבודה מהבית מתאימה.
2. **שכר רצוי:** "מה השכר החודשי שהיית רוצה, ברוטו? אפשר טווח."
   - מסבירים: "השכר הזה הוא ציון 5. משרה שצפויה לשלם יותר תקבל יותר, ופחות תקבל פחות. זו הערכה של Claude, כי רוב המודעות לא כותבות שכר."
   - נכתב ל-`desiredSalary`.
3. **מה לסנן מראש:** מילים בכותרת שאומרות "לא בשבילי". הן נכנסות ל-`excludeTitles`, וככה Claude לא מבזבז זמן על משרות כאלה.
   - **מי שלא מחפש תפקיד טכני:** הצע את הרשימה הזו כברירת מחדל:
     - באנגלית: engineer, developer, architect, devops, sre, firmware, asic, rtl, silicon, algorithm, data scientist, researcher, technician, software, hardware, backend, frontend, full stack, qa, intern, student
     - בעברית: מהנדס, מפתח, פיתוח תוכנה, בודק, טכנאי, אלגוריתמ, ארכיטקט, סטודנט
   - **מי שמחפש תפקיד טכני:** שאל מה לא רלוונטי לו.
4. **תחומים:** בחר מראש את התחומים שמתאימים לפי הריאיון, והצג ברשימה ממוספרת רק תחומים שיש בהם לפחות חברה אחת, עם מספר החברות בכל תחום (סופרים לפי `sector` ב-`companies.json`). ליד תחום עם פחות מ-3 חברות כתוב בגלוי "(כרגע רק X)", כדי שלא יצפה ליותר. סמן ✅ ליד אלה שבחרת. "אלה התחומים שנראים לי מתאימים. רוצה להוסיף או להוריד? כתוב את המספרים."
   - כל החברות בתחום שנבחר נכנסות.
   - הרשימה המלאה של החברות נמצאת ב-`COMPANIES.md`.
   - נכתב ל-`sectors`, עם המפתחות: banks, insurance, fintech, hitech, defense, industry, pharma, health, retail, telecom, energy, transport, realestate, public, education.
5. **AllJobs:** כבוי כברירת מחדל (`alljobs: false`). מזכירים במשפט: "אפשר להוסיף גם משרות מ-AllJobs. התקנון שלהם לא מתייחס לשימוש כזה, ולכן זה על אחריותך. רוצה?" רק מי שאומר כן מקבל `true`.
6. **שעות הריצה:** ברירת המחדל היא 10:00 ו-18:00 (`runTimes`). שואלים רק אם המשתמש מעלה את זה.
7. מריצים `npm run check`. כל השורות עד "הוגדר שכר רצוי" צריכות להיות ✅.

## שלב 3: מגדירים מייל
**למה:** כך הסיכום מגיע לטלפון אחרי כל ריצה. בלי מייל, הסיכום נשמר רק בדוח במחשב.

1. **מסבירים:** "כדי שהסוכן ישלח לך מייל מחשבון ה-Gmail שלך, צריך 'סיסמת אפליקציה'. זו סיסמה מיוחדת של 16 אותיות, רק בשביל הסוכן. היא לא הסיסמה הרגילה שלך, ואפשר לבטל אותה בכל רגע. היא נשמרת רק במחשב שלך, בקובץ שאני לא קורא."
2. **מנחים, צעד אחר צעד:**
   1. נכנסים ל-https://myaccount.google.com/apppasswords
   2. אם כתוב שהאפשרות לא זמינה, צריך קודם להפעיל אימות דו-שלבי: https://myaccount.google.com/signinoptions/twosv ואז לחזור לקישור הקודם.
   3. בשם האפליקציה כותבים "סוכן משרות", ולוחצים "יצירה".
   4. מעתיקים את 16 האותיות שמופיעות.
3. **מכינים את הקובץ:** מעתיקים את `.env.example` ל-`.env` ופותחים אותו: `notepad .env`. המשתמש מדביק:
   - ב-`GMAIL_USER`: כתובת ה-Gmail.
   - ב-`GMAIL_APP_PASSWORD`: הסיסמה.
   - שומר וסוגר. **אל תפתח ואל תקרא את הקובץ.**
4. **בודקים:** `npm run check -- --mail`. צריך להופיע "✅ ההתחברות ל-Gmail עובדת".
   - **נכשל:** בדרך כלל הודבקה הסיסמה הרגילה, או שיש רווח בכתובת. מבקשים לפתוח שוב את הקובץ ולבדוק.
5. **מי שמדלג:** הסוכן עובד גם בלי מייל. אפשר להגדיר אחר כך: "תגדיר לי מייל".

## שלב 4: ריצה ראשונה ותזמון
1. **מפעילים את התזמון:** `node scripts/schedule.mjs on 10:00 18:00`, עם השעות מ-`runTimes`. מסבירים: "מעכשיו המחשב מריץ את הסוכן לבד פעמיים ביום, וביום ראשון ב-08:00 נשלח סיכום שבועי. אם המחשב היה כבוי בשעה הזו, הריצה תקרה כשהוא יידלק. לא צריך להשאיר שום חלון פתוח."
2. **ריצה ראשונה, עכשיו:** `node --no-deprecation job-agent.mjs`. מסבירים: "הריצה הראשונה ארוכה, 10–20 דקות, כי כל המשרות חדשות. הבאות קצרות בהרבה." בזמן הריצה ענה על שאלות אם יש.
3. **בסוף:** פותחים את הדוח (`start "" reports\latest.html`) ומספרים מה נמצא: כמה משרות, ו-3 המובילות עם הציון וההסבר. אם הוגדר מייל: "המייל הראשון בדרך".
4. **מסיימים בהסבר על השימוש היומיומי** (מהטבלה ב-`CLAUDE.md`), בחמש שורות:
   - "הגשתי למשרה X"
   - "משרה X לא רלוונטית"
   - "תתאים קורות חיים למשרה X"
   - "מכתב מקדים למשרה X"
   - "תוסיף את חברה X"
   - **ומשפט סיום:** "מספר המשרה מופיע בכל כרטיס במייל ובדוח."
5. כותבים ב-`data/setup-progress.md`: "ההקמה הושלמה".
